# Uptime 24

A pixel-art news channel that reports the state of your services as a live broadcast.
Two presenters read out incidents and announcements, a weather forecaster shows every
service on a forecast board, and breaking news interrupts the programme.

It is a standalone tool: it shares this repository but does not depend on Serveradmin.

## Run it

```sh
cd uptime24
cp .env.example .env      # then set ADMIN_PASSWORD
docker compose up -d --build
```

- Broadcast: `http://<server>:8080/` (put it fullscreen on a TV, or capture it with OBS to stream it)
- Admin interface: `http://<server>:8080/admin` (sign in with `ADMIN_USER` / `ADMIN_PASSWORD`)

Configuration and cached voice clips live in the `data` volume, so they survive restarts
and rebuilds. Without Docker: `ADMIN_PASSWORD=... node server.js` (Node 20 or newer, no
dependencies to install).

| Variable             | Meaning                                                                 |
|----------------------|-------------------------------------------------------------------------|
| `ADMIN_USER`         | Admin sign-in name, default `admin`                                     |
| `ADMIN_PASSWORD`     | Admin password, required by the compose file                            |
| `PORT`               | Port published on the host, default `8080`                              |
| `ELEVENLABS_API_KEY` | Optional. Switches the presenters to ElevenLabs voices                  |

## Admin interface

**Put something on air.** Type a headline and a text; the presenters read it within a few
seconds and repeat it in the news rotation until it expires or you remove it. Tick
"Interrupt the programme as breaking news" to cut in immediately.

**Information channels.** Addresses the server pulls on a schedule:

| Type            | What to enter                                   | What it produces                                   |
|-----------------|--------------------------------------------------|----------------------------------------------------|
| Status page     | A page in Atlassian Statuspage format, e.g. `https://status.example.com` (`/api/v2/summary.json` is added for you) | One service per component, with its open incident and latest update |
| RSS or Atom feed| The feed address                                 | Recent entries, read out as news items             |
| JSON endpoint   | Any address returning the format below           | Services and news items                            |
| Website check   | Any web address                                  | One service, down when the address fails or returns an error |

While no channel is switched on, the broadcast shows invented demo incidents (marked
"DEMO FEED"). Switch that off under Settings.

### JSON endpoint format

```json
{
  "services": [
    { "name": "Shop", "status": "degraded", "title": "Slow checkout",
      "phase": "Investigating", "note": "Latest update text.", "since": "2026-01-05T10:00:00Z" }
  ],
  "items": [
    { "title": "Winter event", "text": "Starts Friday at noon.", "severity": "info", "created": "2026-01-05T09:00:00Z" }
  ]
}
```

`status` is `operational`, `degraded`, `outage` or `maintenance`; `severity` is `info`,
`good`, `degraded` or `outage`. Only `name` and `status` (services) and `text` (items)
are required.

## Voice

The Voice button on the broadcast makes the presenters speak. With `ELEVENLABS_API_KEY`
set, lines are generated by ElevenLabs through the server (the key never reaches the
browser) and cached in the data volume for a week. Voice IDs per presenter are set in the
admin interface; empty means a default voice. Without a key the broadcast uses the
browser's built-in speech.

## Things to know before exposing it

- The broadcast and `/api/state` are public by design; only `/admin` is protected, with
  HTTP Basic auth. Put the service behind a TLS reverse proxy if it leaves your network,
  otherwise the password travels unencrypted.
- With an ElevenLabs key, anyone who can reach the broadcast can make the server generate
  speech (limited to 300 characters per line and 40 new lines per minute). Keep it on an
  internal network or behind your proxy's access control if that matters.
- Channel addresses are fetched from the server, so an admin can point it at hosts inside
  your network. Only give the admin password to people you would trust with that.

## Development

```sh
npm test          # parser tests, no dependencies
```

`server.js` is the HTTP server and poller, `lib/sources.js` holds the channel types, and
`public/` holds the broadcast (`index.html`) and the admin interface (`admin.html`).
